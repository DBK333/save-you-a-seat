# SYAS delivery record

Initial delivery date: 29 September 2026. This is the first implementation stage from the approved plan: the desktop demo, service contract, and infrastructure preparation. The application version remains `0.1.0`. The original OpenAPI contract was `1.0.0`; the 30 September coverage revision is `1.1.0`.

## Delivered behavior

The React application supports discovery of sample toilets and meeting rooms, synchronized results and map markers, search and amenity filters, approximate nearest-toilet selection, and external Google Maps walking directions. A published entrance-guide coordinate takes priority over the curated facility entrance. Geolocation is requested only after an explicit action; denied access leaves manual origin selection available.

The desktop flows include regular and staff sign-in, registration, verification, recovery, photo-guide authoring and previews, ordered steps, distinct-account confirmations, revisions, reporting, staff decisions, room reservations, My bookings, and cancellation. Submitted guides are immutable. Reporting preserves visibility; removal blocks subsequent confirmation and revision publication for that guide. Reservations use UTC timestamps and Melbourne calendar rules, including daylight-saving validation.

All facilities, accounts, bookings, and seeded venue illustrations are clearly labelled demonstration data. The local service persists browser state without passwords. API mode and missing production configuration fail closed. Selecting a demo staff profile demonstrates the interface; it does not establish real authorization.

## S3 and CloudFront hosting revision

The approved hosting change replaces Amplify with a private, encrypted, versioned frontend S3 bucket behind CloudFront Origin Access Control. The API Gateway/Python Lambda backend remains a separate origin and future implementation stage. Bootstrap also retains its separate versioned backend-artifact bucket. All public frontend traffic goes through CloudFront HTTPS; there is no public S3 website endpoint.

The SPA rewrite handles desktop routes while preserving static/reserved paths and real missing-asset errors. The publisher uploads assets before `index.html`, sets appropriate cache headers, retains older objects, creates a CloudFront invalidation, and records object versions plus release/invalidation metadata. A labelled frontend demo can be published after bootstrap without creating the missing Python backend. No publishing or deployment has been performed here.

## Australian coverage and room-status revision — 30 September 2026

The user confirmed Cremorne plus University of Melbourne, with official booking links first. The public `/rooms` page now shows four fictional Cremorne rooms, remaining available/reserved half-hour blocks for a chosen Melbourne date, and each room's next available block. Counts exclude elapsed time, respect sample hours and the 14-day horizon, and update after local reservations/cancellations. The chosen date survives room details and sign-in into the booking form. Visible availability and Open now filters refresh every 30 seconds and when the window regains focus.

The University of Melbourne view links to the official DiBS entry point, teaching-space booking process, and library busyness page. It labels eligibility and external booking ownership, makes no live room-slot claims, and distinguishes occupancy from available seats or reservable rooms. These are curated provider links, not invented university room listings or external bookings saved in SYAS. Catalog facilities must identify Australia (`AU`) and Cremorne and fall inside its curated bounds. Map viewport restrictions cover mainland Australia and Tasmania; `region=AU` supplies regional bias. The rectangle is not an exact country border, a Google key restriction, or an IP-based visitor restriction. Supported starting points use a smaller Melbourne window containing Cremorne and Parkville. Out-of-area location results show an explanation and manual selection. Guide entrances are checked on save, submission and confirmation; previously stored invalid published pins cannot override the facility's walking destination.
